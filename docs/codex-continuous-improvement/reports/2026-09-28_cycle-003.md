**Current User Story:** US-R003-P2-01A — Preflight decoded PCM cache expansion before audio transcoding

## Why this cycle exists

The PDF cache-copy path already performs known-size/free-space preflight, but audio transcoding decodes compressed audio into a complete temporary PCM file under app cache before encoding the final output. A compressed source can expand many times in size. Without a decoded-size preflight, conversion can exhaust cache/storage partway through work and fail after significant CPU and battery use.

## Story US-R003-P2-01A

- Estimate 16-bit PCM cache demand from track duration, sample rate, and channel count before creating the temporary PCM file.
- Use saturating arithmetic so hostile/pathological metadata cannot overflow into a small estimate.
- Keep a conservative free-space reserve.
- Reject the conversion before decode when known metadata proves cache space is insufficient.
- Preserve prior behavior when duration is unavailable rather than inventing a false precise estimate.
- Add direct converter-module unit tests for representative PCM expansion and overflow behavior.
- Add converter-module unit tests to authoritative continuous CI.
