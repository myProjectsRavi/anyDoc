## Source evidence
`BatchQueueForegroundService.processQueue` calls `convertWithBestEffortHistory` and only afterward calls `markTaskSuccess`. The helper suspends in optional `recordHistory`. Cancellation during this phase reaches the service cancellation handler with task RUNNING, which calls `markTaskCanceled`, even though `executeTask` already returned a published output.

## Acceptance and validation
- Immediately after `convert()` returns, transition matching RUNNING task to SUCCESS with output path/size before any optional history suspension or cancellation check.
- Preserve genuine conversion failures and cancellation before a published result.
- If history persistence is canceled, propagate cancellation to stop the remaining batch without downgrading published success or double-counting.
- Add deterministic app JVM regressions for canceled history, normal history errors, conversion failures, and exact-once counters.
- Validate exact implementation SHA through authoritative PR GitHub Actions, then synchronize canonical documents. Keep PR #1 draft/unmerged; never touch main.
