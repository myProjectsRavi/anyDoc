## Source evidence
`DocForgeApp.onTrimMemory()` schedules `cleanStaleTempFiles(maxAgeMs = 0L)`; the cleanup filters by `docforge_` prefix, modification time and `ActiveTempFileRegistry.isActive(file)`. The active registry is opt-in and does not guard the interval before registration. Newly created in-flight cache files may be deleted under memory pressure.

## Acceptance / next action
- Do not delete recently modified `docforge_` files on memory-trim callbacks even if not registered yet.
- Preserve deletion of sufficiently stale cache files and protection for registered active files.
- Keep normal startup cleanup semantics, avoid destructive changes to unrelated cache files.
- Add deterministic JVM/Robolectric boundary tests, run authoritative PR CI against exact code/test SHA, then synchronize canonical state.
- PR #1 remains draft; never modify main. No device/emulator/benchmark evidence claimed.
