## Source evidence
`DocForgeTempFileCleanup.clean()` tests `ActiveTempFileRegistry.isActive(file)` and then deletes the file separately. Another thread can register the file between the check and deletion. The registry uses a concurrent set but the multi-step check/delete operation is not atomic.

## Acceptance criteria and exact next action
- Guard active-path registration/unregistration and the cleanup check/delete operation with the same synchronization boundary; preserve existing registry APIs and cleanup age filtering.
- Do not delete a file after its active registration wins the race. Keep stale inactive file reclamation and fresh-file preservation.
- Add deterministic JVM tests for active-file protection, post-unregister cleanup, and concurrent registration/cleanup interleavings; avoid timing-only assertions.
- Run authoritative PR CI on exact production/test SHA; diagnose failures and synchronize canonical state after terminal validation.
