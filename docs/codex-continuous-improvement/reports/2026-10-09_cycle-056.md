# Cycle 056 — Batch task terminal-state integrity

**Status:** ACTIVE / INCOMPLETE

## Source evidence
`BatchQueueRuntimeStore.markTaskSuccess/Failure/Canceled` updates task status and counters separately. Repeated/conflicting completion callbacks can overwrite terminal status and double count, while missing task IDs still increment counters.

## Acceptance
Only RUNNING -> SUCCESS/FAILED/CANCELED transitions are accepted; task state and counters change atomically. Duplicate/conflicting terminal calls and absent/queued IDs are no-ops. Existing service behavior remains intact. Add focused app JVM regression tests and validate exact implementation SHA in authoritative PR CI.
