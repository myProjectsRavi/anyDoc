## Source evidence
`removeTask` reads and validates one queue snapshot, then removes the task in an update of a potentially newer snapshot; a task can become RUNNING in between. `updateOutputBaseName` validates QUEUED against one snapshot, then applies the rename with `updateTask` against a newer one.

## Acceptance
Use compare-and-set retry loops for both mutations; only remove non-RUNNING tasks and only rename QUEUED tasks; return failures on missing IDs and invalid statuses; preserve concurrent task updates and other state fields. Add focused app JVM tests and validate exact code/test SHA with authoritative PR CI.
