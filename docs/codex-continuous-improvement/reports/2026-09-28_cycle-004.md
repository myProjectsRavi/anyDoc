# AnyDoc Continuous Improvement — Cycle 004

**Status:** COMPLETE  
**Epic:** E004 — Heap-safe PDF rasterization  
**Feature:** F006 — PDF compressor raster memory budget  
**User Story:** US-R004-P2-01A — Bound PDF compressor page bitmap allocation

## Problem

`PdfCompressor` rasterizes PDF pages to `ARGB_8888` before JPEG embedding. Raster width/height were calculated directly from PDF page dimensions and compression DPI. A malformed or unusually large page could therefore request a very large bitmap and exhaust the application heap.

## Change

Production commit `67bae0bec912a1ceeee7885f15c2976759a7383e` adds a heap-aware raster budget. The page bitmap budget uses one eighth of the available max heap, bounded conservatively and capped at 32 MiB. If the requested page raster exceeds that budget, width and height are reduced proportionally before allocation.

Ordinary pages are not needlessly degraded. The A4/150-DPI regression case retains the expected 1240 × 1754 raster.
