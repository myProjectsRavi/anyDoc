## 1. Executive summary

Cycle 001 began by creating the required long-lived feature branch from current `main`. No autonomous implementation was written to `main`.

The first source audit identified a direct user-data-loss class: several conversion paths created a same-named final output and deleted or overwrote an existing user file. The initial example was `VideoAudioExtractor.createOutputFile`, which explicitly deleted an existing output before conversion. A targeted audit then found the same class in multiple PDF, OCR, scanner-bundle and text-conversion paths. Confirmed paths were changed to use the existing `resolveNonConflictingFile` allocator so a collision produces `_1`, `_2`, etc. instead of destroying the previous output.

The second high-severity issue was an initialization race in `PdfBoxInit.ensure`. The old `AtomicBoolean.compareAndSet(false, true)` published “initialized” before `PDFBoxResourceLoader.init()` completed. A concurrent caller could therefore proceed against an in-flight initialization. Worse, if initialization threw, the boolean remained true and later calls would never retry. The implementation now uses a synchronized retryable one-time initializer that publishes success only after the initialization block returns normally.

The third high-severity issue was cache cleanup under memory pressure. `DocForgeApp.onTrimMemory` could call `cleanStaleTempFiles(maxAgeMs = 0L)`, deleting any `docforge_*` cache file regardless of whether a PDF/audio operation was actively using it. PDF URI-copy files and audio PCM files can live long enough for that race to matter. Cycle 001 introduced a process-local `ActiveTempFileRegistry`; active temp files are registered for their operational lifetime and application cleanup skips them.

Regression tests were added for retry-after-failure and concurrent one-time initialization, active-temp registry lifecycle, and non-destructive output allocation. A GitHub Actions workflow was added to run core PDF JVM tests, assemble the debug APK, and run Android lint on the feature branch.

The present execution environment cannot clone GitHub because its sandbox DNS cannot resolve `github.com`. GitHub source inspection/mutation through the connected repository works, but the local Gradle gate could not be run. The GitHub connector has not yet surfaced a passing workflow result for the latest commit. Accordingly, implemented fixes are **CI_PENDING**, not COMPLETE.

The next work remains safety-first: complete the final-output/cancellation audit, protect partial outputs from failure/cancellation, preserve incoming share state across recreation, remove debug-signing from the production release configuration, then broaden tests and CI.

## 5. Crash audit

### Confirmed and addressed this run

#### P1: PDFBox initialization race
**Files:** `core/pdf/.../PdfBoxInit.kt`

Old behavior:
1. atomic flag flipped from false to true;
2. initialization started afterward;
3. concurrent callers seeing true returned immediately;
4. failure left flag true forever.

Potential effect:
- use-before-initialization race;
- first-use failures;
- non-recoverable process state after transient initialization exception.

Implemented direction:
- `RetryableOnceInitializer`;
- volatile fast path;
- synchronized second check;
- execute initialization;
- publish initialized state only after success;
- leave false on exception.

Complexity:
- fast path O(1), no lock after successful initialization;
- first initialization serialized;
- no material memory overhead.

Required evidence:
- concurrent test;
- failure/retry test;
- Android integration build/test in CI.

Status: **CI_PENDING**.

## 8. Concurrency audit

### Fixed: PDFBox one-time initialization
Covered above.

### Fixed in implementation, CI pending: active temp files
A process-local concurrent set now tracks active temp-file absolute paths.

Concurrency properties:
- register/unregister are thread-safe;
- cleanup only reads membership;
- entries are process-local by design;
- process death cannot leave an active operation, so stale disk leftovers are eligible for later age-based cleanup.

### Remaining
- batch runtime store and service concurrency need dedicated tests;
- output naming is safe against existing files at lookup time, but two truly concurrent operations requesting the same new name can still race between “exists?” and file creation. The shared resolver is not an atomic reservation API.
- If concurrent same-name export is possible, implement a reservation/staging design using atomic file creation or a per-output-directory/name lock.

This race is lower likelihood than explicit overwrite but remains correctness debt.

### Remaining filesystem P1
Many tools write directly to the final output path. If a write/save/encode fails midway or cancellation occurs, a partial/corrupt file may remain under a normal-looking final name.

Required migration:
1. allocate the final non-conflicting destination;
2. create a temporary/staging sibling or app-cache output;

4. flush/close;

7. delete stage on exception/cancellation;
8. publish to MediaStore/history only after final commit.

This must be prioritized for tools that can generate large outputs or receive cancellation mid-loop.

## 15. Output-quality audit

### PDF compression
Raster-based compression deliberately converts vector/selectable page content to images. This can reduce size but materially changes semantics and accessibility. UI copy must disclose the trade-off. Benchmarking must compare not just bytes but legibility/fidelity.

### OCR
Searchable PDF text layer currently uses built-in Type1 Helvetica. This is not a robust global Unicode solution. Non-Latin scripts require an embedded offline font/subsetting strategy or a clearly bounded feature claim.

### Document conversion
DOCX/RTF/CSV/TXT conversion is text-oriented and does not imply full Microsoft Office layout fidelity. UI and naming must not overclaim.

### Redaction
Because redaction is security-sensitive, dedicated generated fixtures must verify content streams plus metadata/annotations/attachments behaviors implemented by the tool. Existing source notes are not sufficient evidence.
