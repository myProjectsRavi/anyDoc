## Finding

ScanImageExporter previously wrote individual scan page images and optional ZIP output directly to final user-visible paths. Failure or cancellation could therefore leave partial results.

## Implementation

- Production refactor: `c47880d484c8436dab60bd185e09a737c6302eb5`.
- Exact test-inclusive candidate: `e71273f59968bb218a8571a5065598db184c2c72`.
- Non-ZIP scan pages now use `withStagedOutputFiles` and publish only after the complete set succeeds.
- ZIP mode writes pages directly into one staged ZIP and publishes only the completed bundle.
- Bitmap recycling remains protected by `finally`.
- Collision-safe naming and result semantics are preserved.

## Regression evidence

`ScanImagePublicationSafetyTest` verifies:
- later scan-page failure publishes no earlier final page;
- ZIP-entry failure publishes no final bundle and leaves no staging residue.
