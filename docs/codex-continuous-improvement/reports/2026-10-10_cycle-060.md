# Cycle 060 — Preset replay concurrency integrity

**Status:** ACTIVE / INCOMPLETE

## Source evidence
`BatchQueueRuntimeStore.replaceQueueWithPreset()` checks isProcessing on an initial snapshot and later assigns a new queue directly. A concurrent start can mark the existing queue as processing after the check and lose its tasks when preset replay publishes a replacement.

## Acceptance
- Validate the entire preset before changing the queue.
- Use an atomic compare-and-set loop, refusing to replace a processing state even under contention.
- Preserve expected errors and queue ordering; add app JVM success, invalid preset and concurrent start/replay tests.
- Validate exact implementation SHA through authoritative PR CI; never modify main and keep PR #1 draft.
