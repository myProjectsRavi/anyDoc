## Source-backed risk
`Context.queryKnownInputSize` currently uses `runCatching` for ContentResolver query and descriptor metadata probes. This catches `CancellationException` and converts it to null, potentially masking a provider cancellation and triggering fallback work. The enclosing coroutine's `ensureActive` does not guarantee detecting a provider-thrown cancellation when the job itself is still active.

## Acceptance
- Preserve the exact `CancellationException` thrown by either metadata probe and skip subsequent probes.
- Ordinary provider query failures still fall back to asset descriptor; successful sizes and unknown-size behavior unchanged.
- Focused deterministic JVM regressions and authoritative exact-code/test-SHA draft-PR nine-gate CI.

## Next executable step
Implement the smallest JVM-testable metadata probe helper that rethrows cancellation and returns null for ordinary recoverable exceptions; use it in both `queryKnownInputSize` probes, add regression tests, review diff and validate exact SHA. Keep PR #1 draft/unmerged; never modify main. No Android device/benchmark claims.
