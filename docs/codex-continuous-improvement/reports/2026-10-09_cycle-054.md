# Cycle 054 — Concurrent batch queue persistence integrity

**Status:** ACTIVE / INCOMPLETE
**Epic:** `E054`
**Feature:** `F056`
**User Story:** `US-R054-P1-01A`
**Branch:** `codex/anydoc-continuous-improvement`

## Source defect
`BatchQueuePersistenceStore.replaceSnapshot(tasks)` accepts an already-fetched list. The mutex protects DAO write serialization, not freshness of `tasks`, so the foreground worker and ViewModel can persist stale state in either order.

## Acceptance
Capture the current tasks only after obtaining the existing shared write mutex, and migrate known callers. Test lock contention deterministically and preserve cancellation, normal persistence failures, recovery, and terminal-row publication.

## Next exact mutation
Implement a pure suspend testable lock-and-capture helper, adopt it in `BatchQueuePersistenceStore`, and migrate service and ViewModel writes to a task provider. Add app JVM regressions and run authoritative CI. Do not touch `main`.
